# math-lab —— 数学书逐小节的可运行实验

一句话原则：**图是副产品，断言才是正主。**
每个小节必须先写出一条「可以被判对错」的命题，再写数值实验去判它。
判不出来 PASS，就说明这一节还没学明白。

## 为什么不用 notebook

一份纯 notebook 的数学仓库，三个月后基本没法维护：diff 看不出来、批量跑不了、没法保证每节都跑过。
这里的做法是**每小节一个普通 .py**，跑 `run_all.py` 自动汇总成一个可点开的 HTML 索引。

## 目录约定

```
math-lab/
├── mathviz/                     # 统一工具层（刻意保持很小）
│   ├── section.py               # Section：书上结论 / 命题 / 检查项 / 图 / 观察
│   ├── num.py                   # 相对误差、收敛阶、数值秩、Hilbert 矩阵…
│   ├── plot.py                  # 中文字体 + 统一配色
│   └── site.py                  # 汇总成 site/index.html
├── data/                        # 共享数据集 + 加载器 + 抓取脚本
├── linear-algebra/              # 试点书 1：线性代数（编号 1.x）
├── grokking-statistics/         # 试点书 2：《精通统计学》(Grokking Statistics)（编号 4.x 起）
├── projects/                    # 贯穿案例（不对应某一本书的某一章）
│   └── cta-trend-filter/        # 编号 10.x：把一段 CTA 策略代码拆成数学
├── run_all.py                   # 跑全部（或指定编号）小节并重新生成站点
└── <书>/<章>/N.N-<小节名>.py
```

编号空间：书本小节按章走（书 1 用 1.x、书 2 用 4.x…）；**贯穿案例固定用 10.x**，
这样站点里能按编号自然排序，又不会互相撞号。

小节脚本的契约只有两条：

1. 模块级有一个 `SEC = mathviz.Section(...)`；
2. 有一个 `def run(sec: Section) -> None`。

所以它既能被 `run_all.py` 收集，也能单独 `python 1.3-xxx.py` 运行。

## 每小节的固定结构

```python
SEC = Section(
    number="1.3",
    chapter="第 1 章 · 解方程组与数值稳定性",
    title="条件数与误差放大",
    claim="书上结论：‖δx‖/‖x‖ ≤ cond(A)·‖δb‖/‖b‖",
    proposition="本节要判决的命题：① ② ③ —— 必须写成能被数字否掉的样子",
)

def run(sec):
    sec.check("命题的名字", ok, "实测数字", tolerance="判定阈值")
    sec.info("只报告不判定的中间量", "…")
    sec.figure("fig-name", fig, caption="图说明")
    sec.observe("实际看到什么 vs 书上说什么")
    sec.pitfall("工程上会踩的坑")
```

三类标记，用来自查「这一节到底该不该写代码」：

| 类型 | 判据 | 处理 |
|---|---|---|
| A | 有可判决的数值命题（收敛阶、上界、稳定性…） | 必须写，且必须有 PASS/FAIL |
| B | 只有几何/直觉（比如向量加法的平行四边形法则） | 只画图，不硬凑断言 |
| C | 纯记号与定义（比如「记 A 的转置为 Aᵀ」） | 直接跳过，不要为了凑数写代码 |

| 4.3 六西格玛与肥尾 | 25σ 的荒谬性 / 真实肥尾 / VaR 方向翻转 / 最值 | P(\|Z\|>6)=1.97e-9、P(\|Z\|>25)=6.1e-138；BTC 超额峰度 4.01，**\|z\|>5 实测 4 次 vs 正态预测 0.001 次**；**95% VaR 正态偏保守 4.4%，99% VaR 正态偏乐观 18.9%**；龙卷风最宽记录 9.45σ |

#### ch05-样本量超能力（3 节 / 18 个检查项）

| 小节 | 判决的命题 | 实测结论 |
|---|---|---|
| 5.1 应用 CLT | 收窄速度 / 精度成本 / 真实数据 / σ→s | 书上例题 6.3578%；**SE 对 n 的幂律斜率 −0.4997**（理论 −0.5）；误差减半要 **4 倍**样本；σ 换成 s 后 n=10 覆盖率掉到 78.0% |

### 一、`projects/cta-trend-filter/` —— 贯穿案例：CTA 趋势策略（编号 10.x）

把一段真实的 CTA 策略代码（均线交叉 + ADX 过滤 + ATR 止损）拆成可判决的数学命题。
数据：`data/btc_usdt_1d.csv`（BTCUSDT 日线 2000 根，币安公开接口）。

| 小节 | 数学主题 | 实测结论 |
|---|---|---|
| 10.1 图会说谎 | 坐标 / 尺度 / 采样密度 | 线性轴与对数轴的回撤排序 **ρ=0.88（不一致但有 25/380 对反序）**；降采样低估回撤（日 53.0% → 周 51.8% → 月 49.4%）；**超 Nyquist 采样把 7 天周期量成 91 天**（理论混叠值 91.0） |
| 10.2 递推平滑 | 一阶线性递推 | 初值遗忘率精确等于 ln(1−1/N)（误差 0.00%，半衰期 9.4 根）；**SMA 滞后 6.5 根 vs EMA 13 根（正好 2 倍）**；降噪能力反过来（EMA 方差是 SMA 的 1.93 倍） |
| 10.3 ADX | 比值 / 量纲 / 不连续决策 | 递推 ≡ 几何加权和（9.5e-16）；**横盘时 ±DI 都是 0 而非 50/50，ADX = NaN**；两种量纲口径的差别只是初值差（前 100 根 4.7e-4 → 尾部 5.6e-16）；ADX 良态（噪声 0.05% → 漂移 0.31）但阈值决策是阶跃（8 根 bar 翻转） |
| 10.4 资金曲线 | 连乘 / AM–GM / 估计量 | **波动拖累 301.6 vs σ²/2 = 303.5 bp/日**；打乱收益顺序：终值相对标准差 1.5e-15 而回撤从 28% 散到 77%；回撤 76.6% → 需涨 328%；Sharpe 标准误理论 0.72 / bootstrap 0.53 |

## 与量化/HFT 的接口

这些小节不是"数学练习"，它们各自对应一段真实代码：

* 1.1 → 相关性矩阵、余弦相似度、因子暴露（高维时余弦相似度失真）
* 1.2 → 批量矩阵运算的顺序与代价（`einsum`、回测向量化）
* 1.3 → 协方差矩阵求逆（组合优化）、Kalman 增益、回归的共线性
* 4.1 → 风控阈值：密度不能当概率用，切比雪夫只能当最坏情况
* 4.2 → 用 N 笔交易估计策略收益：均值够用，尾部不够（止损/风险预算要更大样本）
* 4.3 → VaR/熔断阈值的正态假设在极端分位上是低估风险的
* 5.1 → 回测窗口规划：想把估计误差减半，样本（或交易笔数）要 ×4
* 5.2 → 回测报告的「±x%」是覆盖率承诺，不是「真值落在这个区间的概率」；
  盈亏是重尾分布，30 笔交易的均值区间无论用 t 还是 bootstrap 都不可靠
* 5.3 → **胜率区间别用 Wald**：「30 笔 27 胜」原样套公式会算出上界 100.7%；
  换成 Wilson 才得到能决策的 (74.4%, 96.5%)
