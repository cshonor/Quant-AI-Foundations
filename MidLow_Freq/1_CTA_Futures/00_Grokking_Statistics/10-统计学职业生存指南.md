# 第 10 章 · 统计学职业生存指南

## 本章讲什么

最后一章从**技术**转向**人的因素**。作者的核心判断是：统计素养的价值不在于你会不会算 p 值，
而在于你能不能:

1. 把统计知识和 **SQL、编程、可视化、叙事、行业知识**组合起来；
2. 识别**本末倒置**的岗位（先有解决方案再找问题）；
3. 看清**激励结构**——它决定了你的数据长什么样、老板想听什么；
4. 在压力之下仍然**保持诚实**。

> **本章是 C 类章节**：全章没有可判决的数值命题，因此不配 math-lab 实验脚本。
> 唯一可算的地方（3D 打印耗材那段）在文末做了「延伸推算」，并明确标注书里缺少的那一格。

## 要点

### 相邻技能：SQL / 编程 / 可视化 / 行业

作者给的技能清单，按他自己排的优先级：

| 类别 | 具体内容 |
| :--- | :--- |
| **SQL**（第一优先） | SELECT / WHERE / GROUP BY / ORDER BY / CASE / INNER JOIN / LEFT JOIN；进阶是子查询、CTE、窗口函数 |
| 编程实践 | 面向对象、函数式、单元测试、版本控制（Git）、命令行、安全、大 O 分析 |
| Web 与数据格式 | FastAPI / Flask / Django、JSON、正则、网页抓取、数据管道 |
| 实用算法 | 元启发式（爬山法、模拟退火）、线性/离散规划 |
| 可视化 | 优先条形图/散点图/折线图；**避开 3D 图、双坐标轴、饼图**（角度比长度难比） |

作者那段关于 Python vs C/C++/Rust 的说法值得原样记下：

> Python 是出色的「胶水」语言，但让它跑得快的库（numpy、polars）本身是 C/C++/Rust 写的。
> 因此：**先精通一种语言并产出价值，再按实际需要学第二种**。

**Jupyter 的立场**（作者明确反对把它当工程环境，Joel Grus 同观点）：
notebook 让代码线性化、非模块化、不可复用，单元格乱序运行还会产生难以发现的 bug。
⇒ 与本项目 math-lab 的选择一致：**每小节一个独立 `.py` + `run_all.py` 汇总**，
正是为了 diff 可读、批量可跑、且保证每节都真的跑过。

### 行业决定你对两类错误的容忍度

这段是全书对**精确率/召回率权衡**（第 8 章）最落地的一次应用：

| | Netflix（低风险） | Lockheed Martin（高风险） |
| :--- | :--- | :--- |
| 假阳性意味着 | 用户花两小时看了部烂片 | 把平民误判为目标 |
| 对 FP/FN 的取舍 | FP 便宜 ⇒ 可以激进推荐 | FP 灾难 ⇒ 必须极度保守 |

⇒ 书上那句「你所在的行业决定了你对第一类错误和第二类错误的重视程度」
可以直接翻译成第 8 章的语言：**阈值不是模型的属性，是损失函数（也就是行业）的属性。**
作者还补了一句很实在的：如果你想做全自动预测、又不想为 FP 和 FN 睡不着觉，
那就去低风险行业，或者改用**确定性算法**而不是近似为主的机器学习。

### 五个 W 加一个 H：3D 打印耗材的例子

作者用自己那卷 3D 打印耗材（34 个随机位置、均值 **1.72 mm**、标称 **1.74 mm**、卡尺容差 ±0.02 mm）
演示了「不能只看数据表面」。

**延伸推算（书里没做，我补的）**：把它当成一次假设检验会怎样？

设样本标准差 s = 0.02 mm（与卡尺容差同量级，这是保守估计）：

$$SE = \frac{s}{\sqrt{n}} = \frac{0.02}{\sqrt{34}} = 0.00343,\qquad
t = \frac{1.74 - 1.72}{0.00343} = 5.83 \Rightarrow p \approx 1.6\times10^{-6}$$

**统计上极其显著。** 但作者本人的结论恰恰是「我怀疑这只是噪声」——因为他问的是
**Who / Where / When / How**：

- **Who**：我自己测的，可能夹得太用力，把耗材压扁了 ⇒ 系统性地**低估**；
- **Where**：休斯顿的潮湿气候，耗材吸潮；
- **When**：一年中最潮湿的时候；
- **How**：卡尺本身有没有偏、上次校准是什么时候；
- **Why**：我当时处的心态是「想挑战那个 1.74 的宣传」⇒ 确认偏差已经就位。

⇒ 这就是本章最重要的一条技术洞见，配上第 9 章的语言后非常锋利：

> **t 检验只量化随机误差，而 n→∞ 也压不掉 bias。**
> √n 能把 SE 从 0.02 压到 0.0034，却对「卡尺挤压导致的 −0.02」毫无作用。
> 样本量越大，你只会越**确定地**得到一个偏掉的值。

所以书末那句「不要低估数据的五个 W 在测量更复杂事物时的延伸意义」是有严格含义的：
**增加样本量只能对抗方差，对抗偏差只能靠改变测量方式。**

（注意：这一段用的是我假设的 s = 0.02，书里没有给出样本标准差。
真正的 t 值取决于 s，但**结论方向不依赖具体数值**：只要偏差项的量级与容差同阶，
再大的 n 也救不回来。）

### 激励机制：本末倒置的真正源头

Charlie Munger 那两句：

> 「告诉我你的激励措施，我就能告诉你最终的结果。」
> 「如果你有一套愚蠢的激励体系，就会得到愚蠢的结果。」

Upton Sinclair 那句更狠：

> 「当一个人的薪水取决于他是否理解某件事时，要让他去理解这件事是很困难的。」

作者把它落成了三种压力：**研究压力**（不发论文就没资助）、
**工作压力**（客户想看「能省 10% 运输成本」的模型）、
**创业压力**（VC 想要一个能演的 demo）。这三者正是第 9 章 p-hacking 的动机来源。

**AI 与裁员：一个现成的混杂变量案例。** 作者自己把它当第 9 章的习题做了：
科技高管把裁员归给 AI，但更可能的解释是**货币政策**（利率从宽松转紧）。
两者的时间重合在 2022 年 ChatGPT 上线附近——但**重合不是因果**。
而且把原因说成 AI 比承认「我们招过头了」体面得多，所以这个说法会有系统性的供给偏向。
⇒ 这是全书的收尾彩蛋：**第 9 章讲的混杂变量，第 10 章在自己身上用了一次。**

### 在压力下保持诚实的两个话术

作者给了两条能立刻用的策略（不是心灵鸡汤，是语言层面的操作）：

1. **分享信息，不分享判断**：只说「该演示仅在 X、Y、Z 条件下进行」「事实 A、B、C 如下」，
   不做编辑、不加主观评论。
2. **分享假设，不分享事实**：把可疑论断降级为假设。不要说
   「运输模型 X 将节省 10% 的运输成本」，而要说
   「**目前的假设是**，运输模型 X 将节省 10% 的运输成本」。

配套的还有：私下提问时用「我猜自己可能遗漏了什么……」开场；
触碰政治地雷后判断是「烦恼」还是「威胁」；遇到违法事项咨询**外部**律师而非公司法律顾问。

## CTA / 量化关联

| 本章结论 | CTA 上的直接后果 |
| :--- | :--- |
| 行业决定 FP/FN 的代价 | 期货上 FP = 假突破（亏手续费+滑点），FN = 踏空。**趋势策略默认该容忍 FP**，所以阈值/过滤条件必须按这个偏 |
| 高风险行业要保守 | 杠杆与自动下单属于高风险区；宁可要**确定性规则**（如硬性止损）也不要「模型觉得没问题」 |
| 本末倒置（先有方案再找问题） | 最常见的形态是「我要用深度学习做择时」。正确顺序是：先定义「降低最大回撤 30%」这类战略问题，再选工具 |
| 激励结构扭曲数据 | 卖方研报、策略排行榜、资金方宣传都自带供给偏向；**先问谁出钱、他们要什么指标** |
| 五个 W | 任何因子/数据源先问：谁生成的、在哪、何时采集、为什么采集、怎么标的。**行情口径（复权、换月、是否包含夜盘）就是典型的 Where/How** |
| 偏差压不掉，方差能压 | 回测里最大的偏差源是**未来函数与幸存者样本**，加大样本量只会让你更确定地错 |
| 分享假设，不分享事实 | 对外表述一律写「在 X 假设下，样本内夏普为 Y」，不要写「策略能赚 Y」 |

## 全书收尾

十章走完，作者最后回到一句话：**统计学的中心不是数据与模型，是提出问题并保持好奇。**

对整个 CTA 路线来说，这本书留下的最实用的三条是：

1. **量之前先量尺子**（观测夏普标准差 = 1/√T；9 个样本只有 5 档准确率；
   34 个样本上随机标签的 AUC 有 ±0.20 的噪声）；
2. **样本是消耗品**（每看一次结果它就少一层证据价值，所以三层划分、walk-forward、不许回头改）；
3. **偏差压不掉，方差能压**（幸存者样本与未来函数不会因为回测变长而变好，
   只会让你更确定地错）。
